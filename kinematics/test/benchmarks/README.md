# Kinematics Benchmarks

## RTP vs KDL

`tesseract_kinematics_rtp_vs_kdl_benchmark` compares `RTPInvKin`
(OPW 6-DOF manipulator + 1-DOF revolute tool positioner) against all three
`KDLInvKinChain` solvers on the same 7-DOF ABB IRB2400 + tool positioner
fixture (`base_link` -> `tool_tip`).

### When to use which

The solvers produce fundamentally different solution sets:

- RTP enumerates all manipulator branches at every tool-joint sample.
- The KDL solvers return at most one solution, seed-dependent.

So there is no single number that decides it. `KDLInvKinChainNR` and
`KDLInvKinChainLMA` additionally do not enforce joint limits and may converge
to configurations a planner has to throw away, which is why the benchmark
scores raw convergence and in-limits convergence separately.

Reachability dominates the comparison, which is why both workloads are
registered. On reachable targets KDL wins `time_per_call` by a small factor.
On unreachable ones the ordering inverts by orders of magnitude: RTP rejects a
sample with a norm test, while the KDL solvers iterate to their cap before
reporting failure. A planner that queries near or beyond the workspace boundary
should weight the `UNREACHABLE` rows accordingly.

The benchmark prints a legend explaining every counter, and how to pick a
solver from them, after the results table. That legend lives next to the code
that emits the counters (`rtp_vs_kdl_benchmarks.cpp`) and is the authoritative
description — this file deliberately does not duplicate the counter names.

### Registered benchmarks

Every solver runs over **two workloads**, `REACHABLE` and `UNREACHABLE`, so no row
can be mistaken for a solver's general cost. RTP is additionally swept over a
range of tool-grid resolutions; each of the three KDL solvers — Newton-Raphson
with joint-limit clamping, plain Newton-Raphson, and Levenberg-Marquardt (the
latter two do not enforce limits) — runs in both a warm and a cold seeding
variant. For the exact registered names and arguments, ask the binary:

```bash
tesseract_kinematics_rtp_vs_kdl_benchmark --benchmark_list_tests=true
```

All rows share one measured region (`runIkBenchmark`), parameterised by solver and
seed mode, so a change to what is timed applies to every row at once rather than
needing an identical edit per benchmark.

`WARM` seeds at `ground_truth + N(0, NOISE_SIGMA_RAD)` (0.1 rad ~ 5.7 deg,
clamped back into limits), modelling a planner whose previous step landed near
the current target. `COLD` seeds at the zero vector.

RTP is seeded with `ground_truth`, which is intentional — its inner OPW solver
is closed-form and ignores the seed. That equivalence breaks if the inner
manipulator solver is ever swapped for a seed-dependent one.

### Running

```bash
./colcon_tesseract.sh --packages-select tesseract
. install/setup.bash
./build/tesseract/kinematics/test/benchmarks/tesseract_kinematics_rtp_vs_kdl_benchmark \
  --benchmark_format=console --benchmark_repetitions=3
```

Requires `TESSERACT_ENABLE_BENCHMARKING` (or
`TESSERACT_KINEMATICS_ENABLE_BENCHMARKING`) together with `TESSERACT_BUILD_KDL`
and `TESSERACT_BUILD_OPW`.

### Target set

`REACHABLE` runs `NUM_TARGETS = 256` `tool_tip` poses generated by FK roundtrip
on joint vectors sampled uniformly within each joint's limits, so every one is
solvable by construction. The RNG is seeded deterministically
(`TARGET_RNG_SEED`) so reruns produce identical numbers.

`UNREACHABLE` mirrors that set: same orientations, same seeds, but each
translation pushed out along its own direction to `UNREACHABLE_REACH_SCALE`
times the manipulator reach bound (the same bound RTP derives internally). No
solution exists for any of them, and `selfCheck()` asserts that by requiring RTP
to return zero solutions for **every** target in the set — one solvable pose
would quietly turn these rows back into a partial copy of the reachable ones.

On the unreachable rows `time_per_sol` and `time_per_valid_success` print as
`inf`. That is the arithmetically correct answer for a workload with no
solutions, not a defect; compare `time_per_call` there.

Reported `Time` / `CPU` is per iteration, i.e. all 256 calls. Use the
`time_per_call` counter for per-call comparison rather than dividing by hand.

### Measurement stability

Absolute numbers from this binary are not portable between runs. On a WSL2 host
the same binary has been observed to vary by 25-35% run to run, and running the
full suite reports noticeably slower RTP rows than running `--benchmark_filter=BM_RTP`
alone. Within-run `stddev` is under 1%, so the reported aggregates understate the
real uncertainty.

For A/B work do not compare a number from one build against a number from
another. Build both binaries first, then run them alternately in the same
session and compare per-round pairs. Absolute times are only meaningful relative
to a control measured minutes apart on the same machine.

Cross-workload comparison is the one case where the caution above does not
apply: `REACHABLE` and `UNREACHABLE` rows are produced by the same binary in the
same session, so their ratio is meaningful even though the absolute numbers are
not portable.

### Self-check

`selfCheck()` runs before any benchmark and `abort()`s if a solver reports the
wrong DOF or fails to solve a ground-truth-seeded target. It is deliberately
not `assert()`-based, so it still runs in Release builds where a broken solver
would otherwise produce throughput numbers for broken IK. The per-solution FK
validation inside it is debug-only, being too expensive for Release.

### Caveats

`RTPInvKin`'s `manipulator_reach` is an early-exit filter on the norm of the
back-computed manipulator-tip target — tool_joint samples beyond that radius are
rejected before OPW is called. This benchmark uses the auto-reach constructor,
which derives the radius from the manipulator's base->tip chain via
`computeChainReachUpperBound`. Its cost is paid on every row; its payoff is what
the `UNREACHABLE` rows measure.

How often the filter fires on the `REACHABLE` set is **not** established here.
The bound is an upper bound over the link chain and the targets are FK images of
real joint vectors, which suggests rarely, but no counter reports it — do not
infer a rate from `sols_per_call`, which is also reduced by samples yielding
fewer than eight valid OPW branches.

To change the warm-seed noise magnitude, edit `NOISE_SIGMA_RAD` and rebuild. To
move the unreachable targets further out, edit `UNREACHABLE_REACH_SCALE`.
